TF Monitor: five directions for the interface

The Treatment Failure Monitoring dashboard works and is in use. This paper asks one question only: how should it look and read from here? Five directions are proposed. We need the team to pick one before any build starts.

01

What is being proposed, and what is not

Nothing about the data, the indicators, or the methodology changes. The cascade definitions, the episode-level unit of analysis, the viral-load thresholds and the de-identification pipeline all stay exactly as they are. The same numbers appear in every mockup below, because the numbers are not what is under discussion.

What changes is how those numbers are arranged, weighted and read: layout, typography, density, and how clearly a problem announces itself. The ECEWS green is retained as the primary accent in all five, so programme branding survives whichever is chosen.

One decision, five options. Each direction is a complete point of view rather than a colour scheme. They differ in who they are optimised for — a clinician reading detail, someone monitoring for problems, a reader receiving a report. That is the real choice.
02

The dashboard today

  • Twelve views across three groups — Programme (Overview, Cascade, Deep dive, DTC review, Time metrics, Line list changes), Action (Treatment plans, Advanced analytics) and Reference (Data quality, Guidelines, Methodology, Admin).
  • Three states — Delta, Osun and Ekiti, filterable to LGA and facility.
  • Built as a single HTML file with no build step or framework, served by the FastAPI application. Light and dark themes are already supported.
  • Users are the M&E team, clinical mentors and programme leadership, with role-based access and a read-only viewer account.

The constraint that matters for this decision: because the interface is one file with no build step, a restyle is genuinely a restyle. None of the options below require a rewrite, a framework, or new infrastructure.

03

About the figures shown

Every mockup uses the same real figures, from the snapshot as of 24 July 2026: 3,797 unsuppressed episodes across 3,489 clients, 3,043 commenced on EAC (80.1%), 1,428 completed all three sessions (37.6%), leaving 754 episodes with no valid EAC record (19.9%). Percentages are calculated from those counts. The 15 August upload is deliberately excluded — a defect in the register append inflated it, and it has since been corrected.

One exception, flagged where it appears: the facility list in direction 05 uses real site names but illustrative counts.
04

The five directions

Each is shown on the same Overview screen, so the comparison is of design and not of content. The frames scroll sideways on a narrow display.

01

Clinical Record

densest

Built like a lab report rather than a web application: hairline rules instead of cards, no shadows, no rounded corners, and monospaced figures that align down the column. The whole Overview fits on one screen with no scrolling. The visual language is one clinicians already read fluently — it resembles the paperwork, so it inherits the trust.

02

Operations Console

status-first

Dark, compact, built for a screen someone keeps open all day. Every tile carries a severity stripe, so what needs attention reads before a single number has been read. The ground is a desaturated blue-slate rather than black, which keeps long sessions comfortable and stops the green accent from glaring.

03

Surveillance Bulletin

most presentable

Treats each view as a published bulletin rather than a control panel. A serif carries the headline and the principal figures; generous margins and a single strong rule under the masthead do the rest. Screenshots drop straight into a CDC or partner report without redesign — the page already resembles the document it will end up in.

04

Signal

trend-forward

The closest to a contemporary analytics product. Soft cards, a segmented control in place of a sidebar, and a sparkline inside every tile so each figure carries its own direction of travel. A number without a trend is only half the story; this layout declines to show one without the other.

05

Cohort Board

most opinionated

Makes the cascade the interface rather than a chart inside it. The four stages run left to right as joined panels, and the drop between each is called out on the seam where it happens — the losses are the point, so they carry the emphasis instead of being something the reader calculates.

06

Recommendation

03 Surveillance Bulletin for the Overview and any view leadership sees, with 01 Clinical Record density on Deep dive, DTC review and the facility tables. The two share a palette and a type scale, so they combine without looking like two products: presentable at the top, dense where the work happens.

This is a recommendation, not a decision. If the team's daily reality is closer to monitoring than reporting, 02 is the better answer and the recommendation should be overturned.
07

What we need from reviewers

  1. Which direction, and why? A single preference is more useful than a ranking. If you would combine two, say which for which views.
  2. Who is the primary audience for the Overview? The answer changes the choice more than taste does. If it is leadership and partners, 03 wins. If it is the M&E team working daily, 01 or 02 wins.
  3. Does anything in your daily use get harder? Particularly around density: some directions show fewer facilities per screen. If you scan long tables, say so now rather than after the build.
  4. Any branding or reporting constraint we have missed? Partner templates, print requirements, or accessibility standards that a direction would violate.
08

Next steps

  • Once a direction is chosen, it is built on the Overview page only and deployed for review. Nothing else is touched until that is signed off.
  • The remaining views follow one group at a time, so the dashboard stays usable throughout.
  • No data, indicator or methodology change accompanies this work. Any such change is proposed separately.

Comments to the Data Analytics lead. The mockups above are illustrative renders, not working software — buttons and filters shown are not interactive.
